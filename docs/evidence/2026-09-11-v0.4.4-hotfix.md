# Play&Say pilot hotfix evidence: v0.4.4

Date: 2026-09-11 (Europe/Moscow)

This record is intentionally redacted. It contains no VPN configuration,
keys, client payloads, QR data, credentials, cookies, or TOTP material.

## Incident

- Creating an AWG 3.1 Connection returned `MUTATION_ROLLED_BACK`; Helper's
  internal cause was `adapter validation failed`.
- The current AWG 3.1 configuration passed `awg-quick strip` unchanged.
- A temporary copy with a harmless fixture peer failed only when its basename
  did not match the interface. `awg-quick` reported that the configuration must
  be named as a valid interface followed by `.conf`.
- The same temporary candidate passed when stored in an isolated operation
  directory as `awg0.conf`. It was never applied to the live interface and was
  removed immediately.

## Correction and verification

- Helper apply and rollback now use a private per-operation directory while
  preserving the `<interface>.conf` basename required by AWG 3.1.
- A regression test verifies both the interface basename and per-operation path
  isolation.
- TypeScript lint, typecheck, tests and build; Go format, vet, unit and race
  tests; shell syntax validation; and strict OpenSpec validation passed.
- Release commit: `9454fea`; release tag: `v0.4.4`.
- The amd64 Helper artifact passed checksum and Sigstore verification on the
  target host before installation.

## Deployment safety

- Only the Helper binary was replaced; the prior v0.4.3 binary remains as the
  rollback copy.
- Helper reports version `0.4.4`, protocol `1.0`, status `ok`.
- AWG 3.1 retained its exact container identity, start time, restart count,
  peer count, and configuration fingerprint across the upgrade.
- Panel loopback readiness and the existing public site both returned HTTP 200.
- No test Connection was issued, so the operator can retry the intended
  one-time issuance directly from the authenticated browser session.
