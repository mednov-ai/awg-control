# Play&Say pilot rollout evidence: v0.4.3

Date: 2026-09-11 (Europe/Moscow)

This is a redacted operational record. It intentionally excludes VPN
configuration contents, peer public keys, client configuration, QR payloads,
credentials, environment values, and private key material.

## Release verification

- Release: `v0.4.3`, source commit `6f4e220`.
- Release workflow completed successfully.
- The signed amd64 Helper artifact passed its checksum and signature checks on
  the target host before installation.
- The Panel image signature was verified before deployment.
- Deployed Panel image digest:
  `sha256:33ab882067b32e52c36bcab2eb88b60f0859d8199b4e982919a42b4d74bc43ee`.

## Baseline and safety checks

- DNS for the public site and Panel resolved to the expected pilot host.
- `nginx` and Docker were active. `k3s` was already intentionally inactive.
- The public site returned HTTP 200 and `nginx -t` passed.
- Panel state and SQLite were backed up before deployment.
- AWG2 and AWG 3.1 container identity, start time, restart count, peer count,
  and redacted source fingerprints were captured before deployment.
- Both discovered instances had exactly one usable IPv4 interface subnet; no
  address or configuration value was printed.

## Deployment and rollback exercise

- Helper `v0.4.3` was installed first and its protocol health response was
  verified before updating Panel.
- The host's legacy Docker Compose 1.29.2 failed its first recreate attempt with
  `KeyError: 'ContainerConfig'`.
- The Panel-only rollback restored `v0.4.2`, and loopback readiness returned
  HTTP 200. The named data volume, nginx, the public site, and both AWG
  containers were left untouched.
- The upgrade was then completed by replacing only the disposable Panel
  container while preserving its named data volume.

## Post-deployment verification

- Panel image `v0.4.3` is healthy with restart count 0.
- Helper reports version `0.4.3`, protocol `1.0`, status `ok`.
- Loopback readiness returns HTTP 200; the public login page returns HTTP 200.
- The authenticated public API remains protected and returns HTTP 401 without
  a session.
- The public site returns HTTP 200 and `nginx -t` passes.
- `nginx` and Docker remain active; the pre-existing `k3s` inactive state is
  unchanged.
- AWG2 and AWG 3.1 retained their exact container identity, start time, restart
  count 0, peer counts (9 and 0), and source fingerprints. No VPN container was
  restarted and no peer changed.
- Browser smoke testing confirmed that Create connection offers both AWG2 and
  AWG 3.1 and no longer asks for VPN address CIDR. The modal was closed without
  issuing a connection.

## Deliberately outstanding acceptance

- TOTP enrollment and the complete remembered-login/session-revocation flow
  require operator interaction.
- A disposable Connection was not created during this rollout. Its one-time
  configuration/QR and revoke flow remain a separate explicitly controlled
  acceptance step.
